# StreamStrike: OBS source-first foundation

This candidate selects the real official OBS Studio source at
`72e86655715d9a25d69ce446aa4dd44ba58e10d2`, not `src/bin/editor.rs`.
This is a pinned development comparison baseline, not an accepted release.
The actual engine is C/C++ libobs and the actual original frontend is Qt.
**No Rust port, native runtime acceptance or StreamStrike release is claimed.**

## Reproducible source and build

`python3 tools/obs_foundation.py fetch` creates a NEW `foundation/obs-studio`
checkout with version tags/history at the exact pin and initializes its pinned recursive submodules.
It refuses to overwrite any existing directory. `verify` checks official origin,
commit, usable upstream version tags, clean tracked source, SHA-256 hashes of original build/license/source
files, and presence of the original frontend. No custom editor fallback exists.

The `OBS source foundation` hosted job executes the pinned upstream
`.github/actions/build-obs` with its original Ubuntu build entrypoint, CMake
presets, dependency checksums, original frontend and libobs. It uses the same
`ubuntu-26.04` runner as the audited upstream workflow. No signing credentials
or paid services are added. Native capture/recording acceptance is a separate
required step; compilation is insufficient. Only provenance is uploaded, not a
binary release. The guardrail tests use exact API-retrieved source fixtures;
mocked Git calls are NOT evidence of a real checkout or successful build.

## Preservation / removal map

| Existing path | Decision |
| --- | --- |
| `src/bin/editor.rs` | Retired from the active tree after the original OBS build passed. Recoverable in Git history; no replacement custom UI. |
| Root `Cargo.toml` and old GUI workflow | GUI target/dependencies and screenshot workflow retired; compatibility CLI/library and its tests retained. Default developer command launches original OBS. |
| `src/lib.rs`, `src/editor.rs`, `src/storage.rs`, `src/main.rs` | Preserve existing JSON models, validation, storage and CLI as legacy import/export compatibility utilities, not OBS engine. Assess importer mapping before any removal. |
| User JSON projects, scenes and media | Never deleted or automatically overwritten. Original copies remain; conversion must write separately with explicit diagnostics for unsupported fields. |
| Logos, notices, approved documentation | Preserve assets; update stale claims and screenshots only when source-matched replacement is real. |
| Git history and existing contributions | Preserve; no history rewrite. |

The earlier `docs/DECISIONS.md` choice of a custom editor with OBS as a possible
future adapter is superseded by this explicit OBS source-first selection.

## Rust migration, without another replacement UI

First bounded slice: study the pinned `libobs/obs-data.c` user/default/autoselect
value precedence, ownership and serialization behavior; implement a separate
Rust parity module with differential fixtures generated by the original C
implementation. Preserve original frontend/engine until parity and ABI/lifetime
review pass. Do not replace the Qt UI or claim a JSON schema is a capture engine.
Later slices must retain scene/source, mixer, recording and output behavior.

Acceptance remains: real display and microphone capture, preview, bounded
recording, stop/finalize, independent decode, and device-loss/disk-full handling.

`libobs/obs-data.c`). `evidence/upstream/COPYING` is verbatim upstream COPYING;

and appropriate notices. No binary release is part of this change.
